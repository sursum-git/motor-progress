# Segurança de consultas por consumidor — desenho

Pedido autorizado: implementar tokens por consumidor, permissão explícita por consulta e proteção administrativa, publicar e validar em sursum-api/med HTTPS 9911.

Implementação final: política ABL compartilhada, sem migração de banco, com configuração JSON protegida contendo somente hashes SHA-256, identificador, perfil, ativação, expiração UTC e lista exata de códigos. Token aleatório de 256 bits no cabeçalho X-Sursum-Query-Token, nunca por URL ou body. O adaptador instalado não encaminhou Authorization ao CGI; o cabeçalho dedicado foi comprovado no PASOE. Sem configuração válida, acesso negado. Consumidor executa somente POST /SursumDynamicQuery/query por code autorizado; consultas livres e todos os demais endpoints do handler dinâmico exigem admin. OPTIONS não executa dados e fica disponível.

Um novo handler SecuredDynamicQueryWebHandler envolve o handler atual. Por determinação expressa do usuário, somente sursum-api/MED/9911 recebe essa política: defaultHandler MED e catch-all em ROOT.handlers, preservando os mappings independentes anteriores. IMA e demais instâncias mantêm a política anterior. Não alterar SursumPrograms ou sua autenticação existente por analogia. O wrapper autentica antes da execução e delega ao handler original. Hooks mínimos no base recebem a identidade autenticada, evitando que X-Sursum-User forje a auditoria; não ativam a política em outros contextos.

O proxy PHP mantém login obrigatório e recebe token administrativo exclusivamente de arquivo fora da raiz web, sem expô-lo ao navegador ou ao cadastro de contextos. É uma credencial da ferramenta interna: o login web continua sendo a fronteira dos operadores humanos existentes. Não cria novas permissões humanas.

Administração dos consumidores por CLI local confiável, com gravação atômica, hash apenas, expiração e revogação; não expor API de cadastro de tokens. Token gerado é mostrado uma única vez ao operador da CLI. Nenhuma credencial em Git. O proxy exige HTTPS e pin da chave pública obtido via SSH autenticado, pois o certificado atual é autoassinado sem SAN. Pin incorreto bloqueia antes do HTTP. A credencial/pin só se aplicam ao host/porta/caminho exatos de sursum-api/MED/9911; demais PASOEs preservados. Nenhuma mudança de firewall.

Testar negativas antes de qualquer efeito: token ausente, malformado, incorreto, expirado/inativo; consulta não autorizada; tentativa de body livre, async ou propriedade extra; config ausente/inválida; rotas administrativas; comparação exata de códigos sem glob/case folding. Positivas: consulta permitida e admin. Token de teste efêmero e retirada após smoke. Compilar e testar 12.2; local12.8 somente diagnóstico. Publicar via manifesto/hash/backup, registro do handler por último, recarga apenas MED ocioso e comprovar HTTPS9911.

Conclusão: acesso autorizado pelo usuário permitiu compilação oficial 12.2.12, publicação e validação real. Passaram 52 checks ABL em cada uma das quatro combinações de encoding/formato numérico, cinco testes CLI, 21 verificações PASOE e 16 checks PHP no servidor publicado, além da leitura completa pelo proxy e rejeição de pin TLS incorreto.
